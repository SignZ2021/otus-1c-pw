### Описание проектной работы

Проектная работа по курсу "Разработчик 1С. Продвинутый уровень" (OTUS)

Тема: **Организация одновременной доработки конфигурации "Управление парком аттракционов" тремя разработчиками**

:arrow\_up:[к оглавлению](https://github.com/SignZ2021/otus-1c-pw/blob/Master/README.md#Оглавление)

### Задание проектной работы

Фирме управляющей парком аттракционов требуется повысить эффективность продажи билетов на аттракционы. Для этого решено обратить внимание на операции продажи билетов. Требуется предоставить практические решения по этому вопросу как на уровне исполнителей, так и на уровне управляющих. Решение задачи реализовать на основе конфигурации "Управление парком аттракционов".

**Условия и требования к проекту:**

* Использование статуса продажи билета - с бонусом/без бонуса в документе "Продажа билета".
* Программная доработка интерфейса формы документа "Продажа билета" для учета нового статуса.
* Программная доработка оформления списка документа "Продажа билета" для учета нового статуса.
* Создание отчета "Продажи по билетам" с оптимизированным запросом.
* Добавление в конфигурацию обработки управления регламентными и фоновыми заданиями.
* Web-клиент для передачи данных о продажах билетов в формате JSON во внешний сервис.
* Периодическая отправка данных о продажах билетов на внешний сервис.
* Web-клиент для передачи данных о продажах билетов должен быть оформлен в виде расширения основной конфигурации.
* Необходима организация одновременной разработки тремя разработчиками с механизмами последующего объединения в итоговой конфигурации через внешний репозиторий.
* Предоставить доступ к внешнему репозитарию для проверки командой курса.

**Что практикуем?**

* Учимся работе с клиент-серверными решениями 1С.
* Учимся программной работе с формами и динамическому изменению интерфейса.
* Учимся работе с технологией СКД.
* Учимся производить оптимизацию запросов.
* Учимся интеграции решений сторонних разработчиков в свои конфигурации.
* Учимся работе с http-сервисами 1С, осваиваем технологию REST API.
* Учимся использовать регламентные задания.
* Учимся реализации задач через расширения 1С.
* Учимся работе с Git и работе в команде через Pull Request.

### Краткая информация о исходной конфигурации

Конфигурация "Управление парком аттракционов" - это не готовое коммерческое решение, а учебная модель, созданная для демонстрации процесса доработки системы. Чаще всего встречается в контексте разработки различных доработок на платформе 1С:Предприятие 8. Информационная база с этой конфигурацией уже имеет первичный набор данных, на которых можно провести проверку и отладку производимых доработок.

:arrow\_up:[к оглавлению](https://github.com/SignZ2021/otus-1c-pw/blob/Master/README.md#Оглавление)

### Этапы работы над проектом

1. Запуск исходной информационной базы "Управление парком аттракционов" в клиент-серверном режиме. Выгрузка конфигурации в текущий репозиторий GitHub в ветку [Master](https://github.com/SignZ2021/otus-1c-pw/tree/Master).
2. Анализ исходной конфигурации и поставленных задач.
3. Формирование конкретных задач по доработкам конфигурации для трех разработчиков:
* *Разработчик 1* - доработка интерфейса документа "Продажа билета" для отражения статуса использования бонусов (см. ветку [Branch1](https://github.com/SignZ2021/otus-1c-pw/tree/Branch1)).
* *Разработчик 2* - создание отчета "Продажи по билетам" и обработки для работы с регламентными и фоновыми заданиями (см. ветку [Branch2](https://github.com/SignZ2021/otus-1c-pw/tree/Branch2)).
* *Разработчик 3* - разработка web-клиента для передачи данных о продажах билетов во внешний сервис (см. ветку [Branch3](https://github.com/SignZ2021/otus-1c-pw/tree/Branch3)).
4. Слияние доработок всех разработчиков через репозиторий в текущей ветке [Master](https://github.com/SignZ2021/otus-1c-pw/tree/Master) с использованием механизма Pull Request:

![-](https://drive.google.com/file/d/1_CGJnhyWIEAsU1zaepoQS3HolZr9ECxM/view?usp=sharing "Схема слияния")

5. Загрузка конфигурации со всеми доработками в исходную информационную базу "Управление парком аттракционов" и тестирование нового функционала.
6. Подготовка и отправка материалов по проекту и передача их на проверку команде курса OTUS.
